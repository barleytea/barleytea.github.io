# 技術記事執筆ワークフロー

このドキュメントでは、barlog.techで技術記事を執筆し、公開するまでの標準的なワークフローを定義します。

## 概要

記事執筆は、以下の6つのステップで進行します。

1.  **企画・アイデア出し**: ネタの選定とゴール設定
2.  **構成作成**: 骨子の設計
3.  **執筆**: Markdownでのコーディング
4.  **推敲と校正**: 品質向上
5.  **プレビューと最終確認**: 公開前のチェック
6.  **公開**: デプロイ

各ステップの詳細は、既存のドキュメントと連携しています。不明な点があれば、以下の関連ドキュメントも参照してください。

-   [コンテンツ管理ガイド](./content-management.md)
-   [開発環境セットアップ](./development.md)

---

## Step 1: 企画・アイデア出し

### 1.1. ネタの収集と選定
- **目的**: 読者にとって価値があり、かつ自分が書きたいテーマを見つける。
- **アクション**:
    - 日々の業務や学習で得た知見をメモする。
    - 解決した問題や、調査した技術トピックをリストアップする。
    - 読者層（例: 同じ課題を持つ開発者、特定の技術の初学者）を意識してテーマを絞り込む。

### 1.2. ゴール設定
- **目的**: 記事の方向性を明確にする。
- **アクション**:
    - 「この記事を読んだ読者がどうなってほしいか」を具体的に定義する。
        - 例: 「〇〇ができるようになる」「△△の仕組みが理解できる」
    - 記事のスコープ（どこまで解説し、どこから解説しないか）を決める。

---

## Step 2: 構成作成

### 2.1. タイトルと見出しの作成
- **目的**: 記事の全体像を構造化し、論理的な流れを作る。
- **アクション**:
    - 記事の核心を表す魅力的で分かりやすい**仮タイトル**を付ける。
    - `h2`, `h3` などの見出しを作成し、記事の骨子を組み立てる。
    - 読者がスムーズに読み進められるよう、見出しの順序を検討する。

### 2.2. ストーリーラインの設計
- **目的**: 読者の理解を助けるストーリーを設計する。
- **アクション**:
    - **導入**: なぜこの記事を読むべきか、何が解決できるかを提示する。
    - **本論**: 具体的な手順、コード、図解を用いて解説する。
    - **結論**: 記事の要点をまとめ、読者が次にとるべきアクションを示す。

---

## Step 3: 執筆

### 3.1. 記事ファイルの準備
- **目的**: [コンテンツ管理ガイド](./content-management.md)の規約に従って、執筆環境を整える。
- **アクション**:
    - `src/contents/` ディレクトリに `YYYYMMDD-article-slug` 形式のディレクトリを作成する。
    - 作成したディレクトリ内に `index.md` ファイルを作成する。
    - アイキャッチ画像や記事中で使用する画像があれば、同ディレクトリに配置する。

### 3.2. Frontmatter の設定
- **目的**: 記事のメタデータを定義する。
- **アクション**:
    - `index.md` の先頭に、以下の必須項目を含む Frontmatter を記述する。
        - `title`: 正式な記事タイトル
        - `created`: 作成日 (YYYY-MM-DD)
        - `path`: URLパス
        - `category`: カテゴリ
    - 必要に応じて、`tags`, `eyecatcher`, `draft: true` などのオプション項目を追加する。

### 3.3. 本文執筆
- **目的**: 構成案に基づき、Markdownで本文を執筆する。
- **アクション**:
    - コードブロックには言語とタイトルを指定する。（例: ` ```java:title=RetryCommand.java`）
    - 画像は相対パスで挿入し、必ず代替テキスト (`alt`) を設定する。
    - 必要に応じて、` ```toc``` ` で目次を挿入する。

---

## Step 4: 推敲と校正

### 4.1. 自動校正
- **目的**: `textlint` を用いて、文章の品質を機械的にチェック・修正する。
- **アクション**:
    - ターミナルで以下のコマンドを実行し、表記ゆれや文法エラーをチェックする。
      ```bash
      yarn lint
      ```
    - 自動修正可能な項目は、以下のコマンドで修正する。
      ```bash
      yarn lintfix
      ```
    - 詳細は [.textlintrc.json](/.textlintrc.json) と [コンテンツ管理ガイド](./content-management.md#文章校正ルール) を参照。

### 4.2. 手動での読み返し
- **目的**: 機械では検出できないニュアンスや論理構成の誤りを修正する。
- **アクション**:
    - 声に出して読み、不自然な箇所がないか確認する。
    - 専門用語が正しく使われているか、説明は十分かを確認する。
    - 第三者の視点で、分かりにくい部分がないかチェックする。

---

## Step 5: プレビューと最終確認

### 5.1. ローカル環境でのプレビュー
- **目的**: 実際の表示を確認し、レイアウト崩れや誤りを修正する。
- **アクション**:
    - 開発サーバーを起動する。
      ```bash
      yarn develop
      ```
    - ブラウザで `http://localhost:8000` にアクセスし、記事ページを表示する。

### 5.2. 最終チェック
- **目的**: 公開前の最終確認を行う。
- **アクション**:
    - [コンテンツ管理ガイド](./content-management.md#公開前チェック) のチェックリストに基づき、全項目を確認する。
        - リンク切れはないか？
        - 画像は正しく表示されているか？
        - レスポンシブ表示は崩れていないか？
        - タイポや誤字はないか？

---

## Step 6: 公開

### 6.1. 公開設定
- **目的**: 記事を公開状態にする。
- **アクション**:
    - `index.md` の Frontmatter から `draft: true` の行を削除するか、`draft: false` に変更する。

### 6.2. Git でのコミットとプッシュ
- **目的**: 変更をリポジトリに反映し、自動デプロイをトリガーする。
- **アクション**:
    - 変更内容をコミットする。
      ```bash
      git add .
      git commit -m "feat(content): add new article '記事タイトル'"
      ```
    - `main` ブランチにプッシュする。
      ```bash
      git push origin main
      ```

### 6.3. デプロイ確認
- **目的**: 記事が本番環境に正しくデプロイされたことを確認する。
- **アクション**:
    - GitHub Actions のワークフローが正常に完了したことを確認する。
    - サイトURL (https://barlog.tech) にアクセスし、記事が公開されていることを確認する。
